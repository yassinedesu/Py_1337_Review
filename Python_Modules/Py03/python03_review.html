What needs correction

ex2 · Tuples · Hashability

Misconception about what "hashable" means

You described hashing as hiding the value and retrieving it by hashing again — that's not what it does. Hashing computes a fixed-size integer fingerprint from a value, used as an index into a hash table for fast lookup. The fingerprint is not reversible — you cannot recover the original value from a hash.

Immutability enables hashability because the hash must never change. If an object mutated after being stored, its hash would change and Python would lose it entirely. That's why lists can't be dict keys but tuples can.

# Tuples as dict keys work because they're hashable
d = {}
d[(1, 2, 3)] = "spawn point"  # ✓
d[[1, 2, 3]] = "spawn point"  # ✗ TypeError: unhashable type: 'list'

ex5 · Generators · Memory explanation

Confused execution flow with memory usage

When asked about the concrete memory difference between a list comprehension and a generator, you described the execution flow instead. The actual answer: a list stores all N elements in RAM simultaneously. A generator holds only one element at a time — memory stays constant regardless of how large the dataset is. Be aware of / review these

enumerate()

More Pythonic than range(len(...)) when you need both index and value. for i, val in enumerate(args[1:], start=1) is the idiomatic way.

int() vs float() for coordinates

Your ex2 converts to int but 3D coordinates should be float. int("2.5") raises an error; float("2.5") works correctly.

Mutable default arguments

Never do def f(lst=[]): — the list is created once and shared across all calls. Use def f(lst=None): lst = lst or [] instead.

Why sys.argv shouldn't be mutated

It's technically mutable, but it's global shared state. Mutating it could break other parts of your program that read it later. Always build a new list from it.

Hash table collision

Two different values can produce the same hash (collision). Python handles this with open addressing or chaining — O(1) is average case, not worst case.

Generator exhaustion

Once a generator is fully consumed it's empty — calling next() raises StopIteration. You can't rewind it. Create a new generator object if you need to iterate again.

dict.get() vs dict[]

d["key"] raises KeyError if missing. d.get("key", default) returns a safe fallback. Useful for the inventory exercise.

set() prints as set()

Know WHY for the evaluation: printing {} would be ambiguous with an empty dict. Python chose set() to be unambiguous in output and in source code.
