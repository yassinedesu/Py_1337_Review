Program structure

How a Python file starts, and how it can be made directly executable.

The __name__ variable

Every Python file has a built-in variable called __name__. Its value depends on how the file is being used:

SituationValue of __name__
Run directly: python3 ft_garden_intro.py"__main__"
Imported by another file"ft_garden_intro" (the module's own name, the filename without .py)
def ft_garden_intro() -> None:
    print("=== Welcome to My Garden ===")

if __name__ == "__main__":
    ft_garden_intro()
Common mistake

When a file is imported, __name__ is not the name of the file doing the importing. It is the name of the imported module itself.

Why it matters

When you import a file, Python runs all of its top-level code. The if __name__ == "__main__": guard keeps your test and demo code from running at import time. It only runs when the file is executed directly. This leads straight into the concept of imports in the next project.

The shebang line

The shebang is the first line of a script. It tells the operating system which interpreter should run the file.

#!/usr/bin/env python3

To run the script directly (without typing python3 in front), you need two things:

  1. The shebang as the very first line.
  2. Execute permission on the file.
chmod +x ft_garden_intro.py
./ft_garden_intro.py

Without chmod +x, you get Permission denied, even with a perfect shebang.

Evaluation

The subject says you will be asked to add the shebang to your script live. Practice it, including the chmod.

Classes & objects

A class is the model; each instance is one concrete plant.

Class, instance, attribute, method

  • Class: the blueprint (Plant).
  • Instance: one object built from it (rose = Plant(...)).
  • Attributes: the data each instance holds (name, height, age).
  • Methods: the behaviors (show()).
class Plant:
    def __init__(self, name: str, height: float, age: int) -> None:
        self.name = name
        self.height = height
        self.age = age

    def show(self) -> None:
        print(f"{self.name}: {self.height}cm, {self.age} days old")

rose = Plant("Rose", 25, 30)
rose.show()

Function vs method

A method is a function defined inside a class. A function is called by its name alone (print_info()). A method is called through an instance with dot notation (rose.show()).

What is self?

self is the instance that called the method. It is a naming convention (not a keyword), but everyone uses it.

Python passes it for you

You write rose.show() with zero arguments, yet show(self) expects one. Python silently translates the call into Plant.show(rose): the object before the dot becomes the first argument.

State & behavior

Methods that change the object, and per-instance data.

Don't hardcode the growth

If grow() does self.height += 1, every plant grows at the same speed. To let plants differ, store the rate as an attribute set at creation:

def __init__(self, name: str, height: float, age: int,
             growth_rate: float) -> None:
    self.name = name
    self.height = height
    self.age = age
    self.growth_rate = growth_rate

def grow(self) -> None:
    self.height += self.growth_rate

rose   = Plant("Rose", 25, 30, 0.8)     # 0.8 cm/day
cactus = Plant("Cactus", 15, 120, 0.1)  # 0.1 cm/day

Each instance carries its own rate. grow() does not need to know the specific value.

Simulating a week

start = rose.height
for day in range(1, 8):          # 7 iterations: days 1..7
    rose.grow()
    rose.age_one_day()
    print(f"=== Day {day} ===")
    rose.show()
print(f"Growth this week: {round(rose.height - start, 1)}cm")
Off-by-one

range(6) gives 6 iterations (0 to 5). For 7 days use range(1, 8), which also gives you the day number directly.

Name clash to be aware of

The subject asks for a method called age(). If you also have an attribute called self.age, the instance attribute shadows the method and calling plant.age() fails. That is why your earlier version stored the number in self.days. Pick a different internal name (self.days, or self._age once you reach encapsulation) so that age() stays a method.

__new__ vs __init__

Creating an object and initializing it are two separate steps.

MethodRoleWhen
__new__The true constructor: allocates memory, creates the object and returns itCalled first
__init__The initializer: fills the already-created object with your valuesCalled second, on the object __new__ returned

Many people loosely call __init__ "the constructor". It is technically the initializer. You almost never override __new__, but you should know it exists.

Why bother with __init__ at all?

Compare creating and then setting attributes line by line (rose = Plant(), rose.name = ..., rose.height = ...) with passing everything at creation. The second is shorter, less repetitive, and the object is ready to use immediately. It can never exist in a half-filled state.

Encapsulation

Protect data so it can't be corrupted from the outside.

Think of a coffee machine: you insert money and press a button, without touching the internals. Getters and setters are the buttons. The attributes are the internals.

Three levels of naming

SyntaxMeaningWhat Python does
self.heightPublicNothing
self._heightProtected (convention)Nothing. It is a signal to other developers
self.__height"Private" via name manglingRenames it to _Plant__height
Correction

__height is not truly inaccessible. Python mangles the name, so rose._Plant__height still works. It only makes accidental access harder. The subject explicitly asks for the single underscore, not mangling.

Python's philosophy

"We're all consenting adults here." The underscore is a social contract between developers, not a technical lock. Python trusts you not to touch what is marked protected.

Getters, setters, validation

class Plant:
    def __init__(self, name: str, height: float, age: int) -> None:
        self.name = name
        self._height = 0.0
        self._age = 0
        self.set_height(height)
        self.set_age(age)

    def set_height(self, height: float) -> None:
        if height < 0:
            print(f"{self.name}: Error, height can't be negative")
            print("Height update rejected")
        else:
            self._height = height
            print(f"Height updated: {height}cm")

    def get_height(self) -> float:
        return self._height

The setter validates before storing. If the value is invalid, the data stays unchanged and an error message is printed from inside the class. set_age and get_age follow the same pattern.

Inheritance & super()

Specialized plants reuse everything a plant already knows how to do.

class Flower(Plant): gives Flower automatic access to all of Plant's methods (grow(), age(), show(), and so on). You only write what is new.

What is super()?

super() is not a constructor. It is a built-in function that returns a proxy to the parent class. Through it you can call any parent method, not only __init__.

  • super().__init__(...) calls the parent's initializer
  • super().show() calls the parent's show()
  • super().grow() calls the parent's grow()

Overriding show() without duplicating code

class Flower(Plant):
    def __init__(self, name: str, height: float, age: int,
                 color: str) -> None:
        super().__init__(name, height, age)   # Plant's part
        self.color = color                    # Flower's part

    def show(self) -> None:
        super().show()                        # Plant's output
        print(f" Color: {self.color}")     # Flower's extra
Why this design wins

The common display logic lives in one place. Copy-pasting it into every subclass wastes lines and makes every future change a multi-file edit. Subclasses just add what is unique to them.

Common mistake

Printing everything with manual print() calls outside the classes. The subject expects each class to own its display through a show() method, extended via super().

Evaluation

Static, class & nested

Three kinds of methods, plus classes living inside classes.

The three kinds of methods

Works ona specific instancenothing, just logicthe class itself
Typical useread or modify instance datautility related to the classalternative constructor
Called asrose.grow()Plant.is_older_than_a_year(400)Plant.create_anonymous()

Static method

A function that logically belongs to the class but needs no instance data. It could live outside the class; you put it inside to keep things organized.

@staticmethod
def is_older_than_a_year(age: int) -> bool:
    return age > 365

Plant.is_older_than_a_year(400)   # True
Plant.is_older_than_a_year(30)    # False

Class method and cls

cls is to the class what self is to the instance. When you call Plant.create_anonymous(), Python automatically passes Plant itself as cls. So cls(...) is the same as Plant(...).

@classmethod
def create_anonymous(cls) -> "Plant":
    return cls("Unknown plant", 0, 0, 0)

anon = Plant.create_anonymous()
The key difference

A static method doesn't know about the class or any instance. A class method knows about the class, so it can create instances of it. This is also why it works well with inheritance: called on a subclass, cls is that subclass.

Self vs cls in one line

self → the specific instance that called the method. cls → the class the method belongs to.

Inheritance chain not yet practiced

Exercise 6 adds Seed, which inherits from Flower, which inherits from Plant. Each level calls super() on the level above, so show() output accumulates naturally: Plant line, then Color, then Seeds.

Nested classes preview only

A class defined inside another class. In this exercise, each Plant owns a nested statistics class that counts its calls to grow(), age() and show(). We did not go deep on this yet; here is the shape to expect:

class Plant:
    class _Stats:
        def __init__(self) -> None:
            self._grow_calls = 0

        def count_grow(self) -> None:
            self._grow_calls += 1

    def __init__(self, ...) -> None:
        self._stats = Plant._Stats()   # one Stats object per plant

The idea: statistics are tightly tied to Plant and make no sense on their own, so grouping them inside the class keeps related logic together. Each instance gets its own counters, and encapsulation applies here too.
