PY_10 · Python 3.10+

FuncMage Chronicles — every concept explained

Five exercises, one idea: functions are values. This page walks through each concept: what it is, the problem it solves, how it works inside Python, when to use it, and the mistakes that trip people up.

Chapter 0

Foundations you need first

Three small ideas that every later exercise relies on.

Everything in Python is an object, including functions

When you write def heal(...), Python creates a function object and binds the name heal to it. The name is just a label. You can attach that label to another variable, put the object in a list, or pass it into another function.

def greet(name):
    return "Hello " + name

hello = greet          # no parentheses: we copy the reference, not call it
print(hello("Ash"))    # Hello Ash
print(greet("Ash"))    # same object, same result
Common mistake greet and greet() are completely different. Without parentheses you hold the function. With parentheses you run it and hold its result.

Lazy iterators

map() and filter() do not return lists. They return iterator objects that compute values one at a time, only when asked. Nothing happens until you loop over them or wrap them in list().

AnalogyA recipe card versus a cooked meal. The iterator is the card; list() is cooking it.

It also means an iterator can only be consumed once. After you loop through it, it is empty.

Type hints

Annotations like def f(x: int) -> str do not change how the code runs. They document intent and let tools (mypy) catch mistakes before you run anything. The subject requires them on every function signature and return type.

For callables use from collections.abc import Callable, not typing.Callable.

Exercise 0 · lambda_spells.py

Lambda Sanctum

Authorized: map, filter, sorted, min, max, round, sum, len. Rule: use lambdas, not def, for simple one-off operations.

Lambda expressions (anonymous functions)

What it is

A function with no name, written as a single expression: lambda parameters: expression. The value of the expression is automatically returned.

Problem it solves

Many built-ins need a tiny function (“sort by this field”, “keep items matching this test”). Writing a full def block, naming it, and placing it somewhere else is noisy. A lambda puts the logic right where it is used.

How it works inside

Python builds the same kind of function object as def does. The only differences: no name (it shows as <lambda> in tracebacks), and the body must be exactly one expression. No statements, no assignments, no return keyword.

# These two behave the same way:
def double(x):
    return x * 2

double = lambda x: x * 2    # fine to learn from; flake8 (E731) dislikes naming a lambda

When to use

  • As a short key= for sorted, max, min.
  • As the test for filter or the transform for map.
  • Anywhere the logic is a single, readable expression used once.

When not to use

  • If you need several statements, loops, or try/except.
  • If you reuse the logic in several places, or it needs a docstring.
  • If you are assigning it to a name (f = lambda ...); flake8 flags that (E731), so use def instead.
AnalogyA sticky note versus a filed document. For a 10-second reminder you write a sticky note. You do not open a new folder.

sorted() with a key function

sorted(iterable, key=func, reverse=False) returns a new sorted list. It calls key(item) once per item, then orders the items by those returned values. The original list is untouched (list.sort() is the in-place version).

artifacts = [
    {'name': 'Crystal Orb', 'power': 85},
    {'name': 'Fire Staff',  'power': 92},
]
sorted(artifacts, key=lambda a: a['power'], reverse=True)
# Fire Staff (92) first, then Crystal Orb (85)
Common mistakeTrying to sort dicts without a key raises TypeError, because dicts cannot be compared with <. Also, for descending order use reverse=True rather than negating values (negating breaks on strings).

filter() and map()

filter(predicate, iterable)

Keeps the items for which the predicate returns a truthy value.

list(filter(lambda mage: mage['power'] >= 75, mages))

map(function, iterable)

Applies the function to every item and yields the results.

list(map(lambda spell: f"* {spell} *", ['fireball', 'heal']))
# ['* fireball *', '* heal *']
Analogyfilter is a bouncer: only some items get through, unchanged. map is a paint booth: every item comes out, changed.
Common mistakeReturning the raw filter/map object when the signature promises list[...]. Always wrap in list().
Good to knowList comprehensions do the same job and are often more readable. The subject wants you to demonstrate map/filter with lambdas specifically.

max(), min(), sum(), round(), len()

  • max(items, key=...) / min(items, key=...) return the whole item whose key is largest/smallest. For a list of dicts you then read ['power'] from the result.
  • sum(numbers) adds an iterable of numbers.
  • len(items) counts them.
  • round(x, 2) rounds to 2 decimals. Average = round(sum / len, 2).
best = max(mages, key=lambda m: m['power'])   # the whole dict
best['power']                                 # just the number
Common mistakeReturning the mage dict instead of its power. Also: mage_stats([]) would divide by zero, so decide how to handle empty input if asked.
Exercise 1 · higher_magic.py

Higher Realm

Authorized: callable(), Callable. Every spell has the contract spell(target: str, power: int) -> str.

First-class functions

“First-class citizen” means the language treats functions like any other value. You can:

  1. Store them in variables and data structures.
  2. Pass them as arguments.
  3. Return them from other functions.
  4. Create them at runtime (lambdas, nested def).

This is the single idea behind the whole module. Everything else is a consequence of it.

Higher-order functions

What it is

A function that takes a function as an argument, returns a function, or both. sorted, map and filter from Exercise 0 are already higher-order; now you write your own.

Problem it solves

Reuse and composition. Instead of writing fireball_x3, heal_x3, freeze_x3, you write one power_amplifier that upgrades any spell.

How it works inside

The outer function runs once and builds an inner function. The inner function keeps access to the outer function’s arguments (that is a closure, formalised in Exercise 2).

spell→power_amplifier(spell, 3)→new spell
AnalogyA recipe modifier. The base recipe is a function. “Triple everything” is a function that takes a recipe and hands back a new recipe.

Callable and callable()

  • collections.abc.Callable is a type hint meaning “anything you can call with ()”. Used in signatures like def f(spell: Callable) -> Callable. The subject asks for collections.abc (the modern location) rather than typing.
  • callable(obj) is a built-in function returning True/False at runtime. Use it to defensively check an argument before calling it.

You can be more precise: Callable[[str, int], str] means “takes a str and an int, returns a str”.

from collections.abc import Callable

Spell = Callable[[str, int], str]   # alias: a spell's contract

callable(len)       # True
callable("hello")   # False

The four patterns you implement

FunctionIdeaReturns
spell_combiner(s1, s2)Call both spells with the same argumentsA spell returning a tuple of both results
power_amplifier(spell, n)Multiply the power before castingA spell with the same signature
conditional_caster(cond, spell)Cast only if cond(target, power) is TrueA spell returning "Spell fizzled" otherwise
spell_sequence(spells)Cast every spell in orderA spell returning a list of results
def power_amplifier(base_spell: Callable, multiplier: int) -> Callable:
    def amplified(target: str, power: int) -> str:
        return base_spell(target, power * multiplier)
    return amplified
Common mistakes
  • Returning base_spell(...) directly instead of returning the inner function.
  • Forgetting to call the received functions inside the inner function.
  • Letting conditional_caster raise an exception instead of returning the string.
Exercise 2 · scope_mysteries.py

Memory Depths

Authorized: nonlocal. Forbidden: global variables.

Lexical (static) scope and the LEGB rule

What it is

“Scope” is the region of code where a name is visible. Lexical means it is decided by where the code is written, not by where or when it is called.

The lookup order

L · Local→E · Enclosing→G · Global→B · Built-in

Python searches the current function first, then any functions that enclose it, then the module, then built-ins (len, print…). First match wins.

x = "global"
def outer():
    x = "enclosing"
    def inner():
        print(x)      # finds "enclosing" (E beats G)
    inner()
Why it mattersYou can read code and know which variable a name refers to without running it. That predictability is what makes closures safe to reason about.

Closures

What it is

An inner function that remembers variables from the enclosing function, even after that enclosing function has returned.

How it works inside

When an inner function uses a variable from an outer function, Python keeps that variable alive in a small “cell” attached to the inner function. You can see them with func.__closure__.

Each call to the outer function creates fresh cells, so two closures made by two calls never share state. That is why counter_a and counter_b are independent.

def mage_counter() -> Callable:
    count = 0                 # lives in the closure cell
    def increment() -> int:
        nonlocal count
        count += 1
        return count
    return increment

a = mage_counter()
b = mage_counter()
a(); a()    # 1, 2
b()         # 1  (separate cell)
AnalogyA mage memorises a spell component before the library closes. The library is gone, but the mage still carries the memory.

When to use

Private state without a class: counters, accumulators, configured functions, callbacks, memory stores.

nonlocal — and why global is forbidden

Assigning to a name inside a function normally creates a new local variable. So count = count + 1 inside increment would fail (the local count is read before it is assigned). nonlocal count says “this name means the one in the nearest enclosing function”.

nonlocalglobal
TargetsVariable in nearest enclosing functionVariable at module level
VisibilityPrivate to that function familyVisible and editable by all code
Side effectsContainedSpread across the program
Two instancesIndependent state eachAll share one value
In this subjectAuthorizedForbidden
Mistake we actually hitnonlocal needs an enclosing function. Using it at module level (for example inside if __name__ == "__main__":) raises SyntaxError: no binding for nonlocal found. See “Bugs we hit”.

Mutable objects as shared closure state

nonlocal is only needed when you rebind a name (count = ...). If the closure variable is a mutable object (dict, list), you can mutate it (d[key] = value, lst[0] = 5) without any keyword, because the name still points to the same object.

def memory_vault() -> dict[str, Callable]:
    private_storage: dict = {}          # one dict, shared

    def store(key: str, value: object) -> None:
        private_storage[key] = value    # mutation: no nonlocal

    def recall(key: str) -> object:
        return private_storage.get(key, "Memory not found")

    return {'store': store, 'recall': recall}

Both store and recall close over the same dict, and nothing outside can reach it. That is encapsulation without a class.

Rule of thumbRebinding a name → needs nonlocal. Mutating an object → does not.

Factory functions

A function whose job is to build and return other (configured) functions. enchantment_factory("Flaming") returns a function that remembers "Flaming".

def enchantment_factory(enchantment_type: str) -> Callable:
    def enchant(item_name: str) -> str:
        return f"{enchantment_type} {item_name}"
    return enchant

flaming = enchantment_factory("Flaming")
flaming("Sword")      # "Flaming Sword"

No nonlocal here: the closure only reads enchantment_type.

Classic trap (good to research)Creating closures inside a loop: [lambda: i for i in range(3)] all return 2, because they share one i that is looked up at call time (late binding).
Exercise 3 · functools_artifacts.py

Ancient Library

Authorized: functools, operator. The point is to use these tools rather than re-implement them by hand.

functools.reduce

What it is

reduce(function, iterable[, initial]) folds a sequence into a single value by repeatedly applying a two-argument function, carrying an accumulator.

[10, 20, 30, 40]→f(10,20)=30→f(30,30)=60→f(60,40)=100
AnalogyPouring buckets together: combine the first two, then combine that result with the third, and so on until one bucket is left.

Edge cases

  • Empty list with no initial value raises TypeError. The subject says return 0, so check if not spells first.
  • Unknown operation name: handle it explicitly (we raise ValueError with a clear message).
operation_map = {
    'add': operator.add,
    'multiply': operator.mul,
    'max': ..., 'min': ...,
}
if operation not in operation_map:
    raise ValueError(f"Unknown operation '{operation}'")
return functools.reduce(operation_map[operation], spells)
Design ideaA dictionary mapping names to functions replaces a long if/elif chain. That is first-class functions in action.

The operator module

Function versions of Python’s operators: operator.add(a, b) is a + b, operator.mul is *, operator.gt is >, operator.itemgetter('power') is lambda d: d['power'].

Why: operators are syntax, not objects, so you cannot pass + to reduce. operator.add is the object form, and is faster and clearer than lambda a, b: a + b.

Peer-review noteThere is no operator.max. For max/min you can pass the built-ins max and min straight to reduce (they accept two arguments), or write a small lambda, as we did.

functools.partial

What it is

Creates a new callable from an existing one with some arguments pre-filled. Also called partial application.

def base_enchant(power: int, element: str, target: str) -> str: ...

fire = functools.partial(base_enchant, 50, 'fire')
fire("Sword")      # same as base_enchant(50, 'fire', "Sword")

How it works inside

It returns a partial object that stores the original function plus the frozen arguments. When called, it merges frozen arguments with new ones and calls the original.

AnalogyA vending machine with three buttons where you glue two of them down. Users only press the third.

partial vs closure

Both freeze values. partial does it for an existing function in one line; a closure is better when the frozen logic needs custom code.

Common mistakePre-filling positionally in the wrong order. If you freeze 50, 'fire' they fill the first two parameters in that order. Keyword form partial(f, power=50, element='fire') is safer.

functools.lru_cache and memoisation

What it is

A decorator that remembers a function’s return values keyed by its arguments. Next time the same arguments appear, it returns the stored answer instantly. “LRU” = Least Recently Used: when a size limit is reached, the oldest-unused entry is dropped. maxsize=None means unlimited.

Problem it solves

Naive recursive Fibonacci recomputes the same sub-problems exponentially many times (about O(2n)). With caching each n is computed once (O(n)).

@functools.lru_cache(maxsize=None)
def memoized_fibonacci(n: int) -> int:
    if n <= 0: return 0
    if n == 1: return 1
    return memoized_fibonacci(n - 1) + memoized_fibonacci(n - 2)

memoized_fibonacci.cache_info()
# CacheInfo(hits=..., misses=..., maxsize=None, currsize=...)

Requirements and limits

  • Arguments must be hashable (no lists/dicts as arguments).
  • The function should be pure: same inputs always give same output, no side effects.
  • cache_info() shows hits/misses; cache_clear() empties it.

functools.singledispatch

What it is

Turns a function into a generic function: which implementation runs depends on the type of the first argument.

Problem it solves

Replaces if isinstance(x, int) ... elif isinstance(x, str) ... chains with separate, independently registered handlers that are easy to extend.

@functools.singledispatch
def cast(spell: Any) -> str:            # fallback for unknown types
    return "Unknown spell type"

@cast.register(int)
def cast_int(spell: int) -> str:
    return f"Damage spell: {spell} damage"

@cast.register(str)
def cast_str(spell: str) -> str:
    return f"Enchantment: {spell}"

@cast.register(list)
def cast_list(spell: list) -> str:
    return f"Multi-cast: {len(spell)} spells"

Details worth knowing

  • Dispatch follows the class hierarchy (a subclass uses its parent’s handler if it has none).
  • Only the first argument is inspected (“single” dispatch).
  • bool is a subclass of int, so True would hit the int handler. Good edge case to know.
Exercise 4 · decorator_mastery.py

Master’s Tower

Authorized: functools.wraps, staticmethod. Hint: time.sleep helps simulate delays.

Decorators

What it is

A function that takes a function and returns a (usually wrapped) function. The line @spell_timer above def fireball() is exactly fireball = spell_timer(fireball).

Problem it solves

Separation of concerns. Timing, validation, logging and retrying are cross-cutting: they apply to many functions but are not part of any function’s core job. A decorator adds them without touching the original code.

Anatomy

def spell_timer(func: Callable) -> Callable:
    @functools.wraps(func)
    def timed_wrapper(*args: object, **kwargs: object) -> object:
        print(f"Casting {func.__name__}...")
        start = time.time()
        result = func(*args, **kwargs)     # run the original
        print(f"Spell completed in {time.time() - start:.3f} seconds")
        return result                      # hand back its result
    return timed_wrapper
  • *args, **kwargs lets the wrapper accept whatever the original accepts.
  • Always return the original result, or you silently break the function.
AnalogyA bodyguard. Every call to the VIP goes through the bodyguard first, who can check, time or retry before letting it through.

functools.wraps

Without it, the wrapper replaces the original’s identity: fireball.__name__ becomes "timed_wrapper" and the docstring is lost. @functools.wraps(func) on the wrapper copies __name__, __doc__, __module__, annotations and sets __wrapped__.

Why it matters: debugging, help(), tracebacks, and the spell_timer requirement of printing the original function’s name all depend on it.

Common mistakePutting @wraps on the outer decorator instead of the inner wrapper, or forgetting it entirely (the evaluation sheet checks for it).

Parameterised decorators (decorator factories)

When a decorator needs its own settings (min_power=10), you add one more layer. Three nested levels:

power_validator(min_power)→ returns →decorator(func)→ returns →validated_wrapper(*args)
def power_validator(min_power: int) -> Callable:
    def decorator(func: Callable) -> Callable:
        @functools.wraps(func)
        def validated_wrapper(*args: object, **kwargs: object) -> object:
            provided_power = cast(int, args[0])
            if provided_power < min_power:
                return "Insufficient power for this spell"
            return func(*args, **kwargs)
        return validated_wrapper
    return decorator

@power_validator(min_power=10)     # call the factory first, then apply
def lightning(power: int) -> str: ...
Common mistakes
  • Writing @power_validator without parentheses (you pass the function as min_power).
  • Applying it directly to a method: args[0] would be self, not power. We solved this by decorating a small inner function whose first parameter is power.

The retry pattern

A decorator factory that catches exceptions and tries again up to max_attempts times.

for attempt_number in range(1, max_attempts + 1):
    try:
        return func(*args, **kwargs)        # success: leave immediately
    except Exception:
        print(f"Spell failed, retrying... (attempt {attempt_number}/{max_attempts})")
return f"Spell casting failed after {max_attempts} attempts"
  • return inside try ends the loop on first success.
  • The failure message sits after the loop, reached only if every attempt failed.
  • Catch Exception, never a bare except: (which would also swallow KeyboardInterrupt).
Real-world noteProduction retries usually add a delay (time.sleep) and exponential backoff, and retry only specific exception types.

class MageGuild:
    @staticmethod
    def validate_mage_name(name: str) -> bool:
        return len(name) >= 3 and all(c.isalpha() or c == ' ' for c in name)

MageGuild.validate_mage_name("Alex")   # True, no instance needed

Also exists: @classmethod, which receives the class (cls). Good to research for contrast.

@staticmethod is itself a decorator: a built-in one.

typing.cast

Tells the type checker “treat this value as type T”. It does nothing at runtime; it only silences a type error you know is safe. We needed it because *args: object makes args[0] an object, and mypy refused to assign it to an int.

Not the same as conversioncast(int, x) does not change x. int(x) does (and would turn 15.7 into 15).

Lessons learned

Bugs we hit and why

1. SyntaxError: no binding for nonlocal 'attempt_count' found

Cause: nonlocal was used in a function defined at module level, where no enclosing function exists.

Fix: use a mutable container instead of rebinding: attempt_counter: list[int] = [0] then attempt_counter[0] += 1. global is forbidden by the subject.

Concept: rebinding versus mutation (see Exercise 2).

2. mypy: Incompatible types in assignment (expression has type "object", variable has type "int")

Cause: *args: object types args[0] as object.

Fix: provided_power: int = cast(int, args[0]).

Concept: typing.cast is a type-checker hint with zero runtime effect.

3. Applying power_validator to a method

Cause: in a method, args[0] is self. The subject says the decorator applies to a standalone function whose first argument is power.

Fix: decorate an inner helper whose first parameter is power, and call it from cast_spell.

Defence prep

Peer-review questions and model answers

Click a question to reveal the answer. Say it in your own words; do not recite.

What is the difference between lambda and def?

Both create function objects. A lambda is nameless and limited to a single expression, so it suits short throwaway logic passed to sorted/map/filter. def gives a name, allows statements and docstrings, and is better for anything reused or non-trivial.

What makes functions “first-class citizens”?

They can be assigned to variables, stored in collections, passed as arguments, returned from functions, and created at runtime, exactly like ints or strings.

How do higher-order functions enable reuse and composition?

You parameterise behaviour instead of copying code. One power_amplifier upgrades any spell, and results can be chained (combine an amplified spell with a conditional one).

From which package should Callable come, and what does callable() do?

collections.abc. Callable is a type hint; callable(obj) is a runtime built-in that returns whether obj can be called.

How do closures “remember” their environment?

Variables used by an inner function are kept alive in cells attached to it (__closure__), so they survive after the outer function returns. Each outer call creates new cells, giving independent state.

Why is global forbidden but nonlocal allowed?

global couples code to module-wide mutable state that anything can change, which breaks functional purity and makes behaviour unpredictable. nonlocal only reaches into the nearest enclosing function, keeping state private and instances independent.

How does functools.reduce aggregate data, and what does lru_cache give you?

reduce folds a sequence into one value with a binary function and an accumulator. lru_cache stores results per argument set, so repeated calls (like recursive Fibonacci) skip recomputation, turning exponential time into linear at the cost of memory.

How do decorators separate concerns?

Cross-cutting behaviour (timing, validation, retry) lives in the decorator, and the decorated function contains only its core logic. You can add or remove the behaviour with one line.

Difference between @staticmethod and an instance method?

An instance method receives self and can use instance state. A static method receives nothing implicit, cannot touch instance state, and can be called on the class itself; it is a plain function namespaced inside the class.

Why use functools.wraps?

To preserve the original function’s __name__, __doc__ and other metadata. Otherwise every decorated function would appear as the wrapper, breaking introspection and debugging.

Why partial and not a lambda?

partial expresses “same function, some arguments fixed” directly, keeps the original’s identity (.func, .args, .keywords), and is the standard tool the subject asks to demonstrate.
